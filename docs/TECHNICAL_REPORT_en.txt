1. ABSTRACT

Report Content

This project uses OpenEvolve to perform full-rewrite evolution on a joint agents + tasks YAML for a CrewAI Sequential Crew, with the goal of maximizing the Simulator combined_score (rating prediction + review quality). We adopt a two-stage staged evolution strategy:

Phase 1 (final_basicOnly): 3 agents x 3 tasks, refine base prompts and the JSON output contract.
Phase 2 (final_agentTask): use Phase 1 Best as Gen-0, extend to 5 agents x 5 tasks, adding historical review matching and internet trend research.

Results:
  Phase 1  Gen-0 0.9100  Best 0.9412  Gain +0.031
  Phase 2  Gen-0 0.9579  Best 0.9999  Gain +0.042

Scoring formula:

  combined_score = (preference_estimation + review_generation) / 2

  preference_estimation: star-rating MAE (50%)
  review_generation: sentiment 25%, emotion 25%, topic 50%

2. KEY FINDING

Report Content

2.1 Strategy-Level Findings (What and How, Creative OpenEvolve Usage)

  1. Human-designed pipeline, machine-optimized prompts
     Topology (agent count, execution order) is human-designed.
     OpenEvolve only optimizes role/goal/backstory and description/expected_output.

  2. Two-stage handoff works
     Phase 2 Gen-0 core agents are text-identical to Phase 1 Best. Handoff verified.

  3. Simple-first avoids search explosion
     Phase 1 plateaus at 0.94 by iter 15. Proves 3-agent ceiling, Phase 2 extension needed.

  4. Historical review matching is largest marginal gain
     analyze_reviews_task + lookup_reviews_by_user_and_item drives iter 45 from 0.9666 to 0.9999.

2.2 Evolution-Level Findings (Strategies OpenEvolve Discovered)

  1. Prompt refinement beats tool swapping
     Phase 1 Best still uses search_*. Gains from prediction_modeler narrative and default strategy.

  2. MAP-Elites tolerates short-term regression
     Phase 1: gen=2 (0.92) below gen=1 (0.94), but gen=3 breaks through to Best.

  3. Oscillation then integration during exploration
     Phase 2: gen=1 to 4 oscillates at 0.94 to 0.95. gen=5 integrates mutations to 0.9999.

  4. Zero structural failures
     292 individuals per run, 0 times combined_score=0. Structure guard stable.

2.3 One-Line Conclusion

  We use two-stage OpenEvolve to push review simulation from 0.91 to 0.9999.
  Phase 1 learns star heuristics.
  Phase 2 completes the final leap at iter 45 via historical review direct match.



3. NOVEL DESIGN

Report Content

3.1 What OpenEvolve Optimizes and How

What: Evolve joint agents + tasks YAML (EVOLVE-BLOCK). Under structure guard, agent/task names and counts are fixed.

How:
  1. Staged handoff: Phase 1 best to Phase 2 Gen-0 plus manually add 2 agents and 2 tasks
  2. Joint bundle: agents and tasks mutate together, personas and instructions co-adapt
  3. Metric-aligned pipeline: early tasks fetch features, mid task matches historical reviews, final task pure reasoning outputs JSON

3.3 Phase 1: 3 Agents x 3 Tasks

  analyze_user_task to analyze_item_task to simulate_review_task
  user_analyst, item_analyst, prediction_modeler

Agents:

  user_analyst
    Role: Yelp User Profiler
    Goal: Analyze user_id
    Backstory: lookup_user_by_id, default 3.8 stars if missing
    Tools: search_user_profile_data, search_historical_reviews_data

  item_analyst
    Role: Yelp Restaurant Analyst
    Goal: Analyze item_id
    Backstory: lookup_item_by_id, reconstruct profile if missing
    Tools: search_restaurant_feature_data, search_historical_reviews_data

  prediction_modeler
    Role: Rating and Review Predictor
    Goal: Predict stars and review
    Backstory: (user_avg+item_stars)/2 plus/minus 0.5 to 1.0, clamp 1 to 5
    Tools: none

Tasks:

  analyze_user_task / user_analyst
    ReAct search_*, Action/Action Input
    Output: Markdown user preferences and rating habits

  analyze_item_task / item_analyst
    ReAct search_*
    Output: Markdown business features, pros and cons

  simulate_review_task / prediction_modeler
    Synthesize prior steps, never claim missing data
    Output: JSON only {"stars","review"}

3.4 Phase 2: 5 Agents x 5 Tasks (Extension)

  internet_research_task to analyze_user_task to analyze_item_task
  to analyze_reviews_task to simulate_review_task to JSON

New agents:

  internet_researcher
    Role: Restaurant Trend Researcher
    Tool: search_internet
    Purpose: General rating trends (max 5 bullets, no fabricated user/item data)

  review_analyst
    Role: Yelp Review Analyst
    Tool: lookup_reviews_by_user_and_item
    Purpose: Direct review match

New task highlights:

  internet_research_task: Never pass description key to tool
  analyze_reviews_task: STEP 1 mandatory lookup, cross-feature fallback
  simulate_review_task: Reference four prior reports, final JSON
